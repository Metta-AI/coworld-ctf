# H1 screen: retain the full octile bound for an exact goal node

The current search subtracts736Q4 units from its octile estimate even when attachments returns exactly one goal node with zero cost. That allowance protects off-lattice endpoint attachments; it is unnecessary in the exact-node case. job.goalNode already records that case. Candidate sets allowance=0 only when job.goalNode>=0, in both initial insertion and pop/relaxation code; all other requests retain736. No new retained field, graph, dependency, queue or runtime flag.

Research before the change: [Hart, Nilsson and Raphael's A* paper](https://ai.stanford.edu/~nilsson/OnlinePubs-Nils/PublishedPapers/astar.pdf) establishes heuristic graph search; [Moving AI Lab's A* demonstrations](https://www.movingai.com/astar.html) show the importance of an appropriate octile estimate and tie handling. Reuse the project's existing integer octile heuristic rather than introducing a library or new search. The following restricted argument is our code-specific inference, not a claim proved by those sources: exact-node endpoints and all fine graph nodes lie on the4px lattice; octileFine uses64/90 while fine edge cost is at least64/91 and bridge cost sums those steps, with non-negative danger/hazard additions. Thus the full octile estimate is consistent and zero at the exact goal. Off-lattice endpoints are deliberately unchanged.
