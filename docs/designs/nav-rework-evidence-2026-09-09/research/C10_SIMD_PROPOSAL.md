# C10 candidate: masked four-lane replay, not full-word specialization

Root hypothesis for peer consideration; no production implementation authorized. C5 found cache replay56%of m5a measured first-fill danger time, and C6 full-word scalar specialization did not clear its10%native micro screen. C7/C9 list representations improved replay but regressed changing-source workloads. This candidate keeps the C2 bitmap and miss recording unchanged and vectorizes masked four-cell additions, including partially set groups. It adds no per-slot list or conversion.

Existing solution research: the project already uses nimsimd1.3.2 (MIT). Its nimsimd/sse2.nim exposes unaligned float loads/stores, integer comparisons, bitwise AND and float adds. Intel documentation defines _mm_and_ps as bitwise mask and SSE packed add as independent lanes: https://www.intel.com/content/dam/develop/external/us/en/documents/18072-347603.pdf and https://www.intel.com/content/www/us/en/docs/intrinsics-guide/index.html. SIMDe offers portable equivalents (https://github.com/simd-everywhere/simde), but adding a dependency is unnecessary for a tools-only native hypothesis screen when existing bindings suffice. Production portability would require an existing NEON/scalar counterpart and exact cross-architecture proof; do not add a new dependency now.

Mechanism: for each nonempty cache word, process contiguous four-cell groups with a nibble mask; zero groups skip. Use a16-entry constant mask table, AND four kernel values, add to four raster values. Keep source order and one addition per visible cell. Only vectorize a group wholly inside both the kernel row and map row; scalar bit traversal handles boundary groups. No reads or writes outside the map even when masked lanes are zero. Add positive zero to inactive lanes only after proving all raster values are finite nonnegative and have no negative-zero representation; otherwise use bitwise blend to retain inactive lanes exactly. No FMA/reassociation/fast-math. Avoid per-group integer division by advancing row position inside a word, but row bookkeeping alone is not the claimed mechanism.

Suggested diagnostic first: reuse C6 corrected map-wide64origin sample and fixed/crafted kernels, profile the nibble occupancy and fraction requiring boundary fallback. Enumerate/reference-compare every index and float result. This is distinct from C6: mixed occupancy is covered, not only all-one64bitwords. Check existing registry for a prior SIMD replay rejection before proceeding.

Suggested preregistration if peer agrees: tools-only native micro on m8i andm5a, three1300px maps plus331px controls, five rotated process pairs, exact inputs/full float rasters. Require at least20%median replay improvement for each1300map on bothhosts, and no331median regression above1%. Then use the existing actual-source traces/changing regimes unchanged before any whole-body candidate. Final absolute gates remain unchanged. This is a proposal; peer should accept, reject or amend before any timed implementation.
