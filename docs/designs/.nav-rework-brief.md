## 1. Problem

Season 2 cogs stand still when they should walk. Two player-visible cases, both verified in code:
- A cog whose life has no route yet: `followerWaypoint` returns the cog's own position when `pathLen == 0` (src/shell/body_nav.nim:687-693), so `seatTick` emits an empty movement mask and records `bnsNoPath` (src/shell/body.nim:1311-1330).
- A cog that reached an older route's endpoint and then receives a new goal: the finished route stays loaded with the cursor on its last point, which equals the cog's position; the state is reported as `bnsStalePath` ("walking an older route", src/shell/body.nim:310) although the mask is zero.

Four mechanisms make it worse:
- `setStandingIntent` cancels any pending plan on every new standing order (src/shell/body.nim:565-590, cancel at :582-583) before `navigationWaypoint` can apply its two-cell goal hysteresis (src/shell/body_nav.nim:726-732), so order churn discards nearly finished work.
- Planning is a resumable weighted A* on a 4 px lattice (src/shell/body_planner.nim:15, :584-640) spread through a pooled budget of 256 work units per configured seat per tick (src/shell/body_nav.nim:31, :572-628). On a giant pool map the lattice has 344,487 nodes; a far route needs ~137k units (task measurement), i.e. hundreds of ticks under one seat's share.
- The round-robin does not prioritise seats with no usable route (src/shell/body_nav.nim:577-598).
- Death only flips `active` (src/shell/episode.nim:987-997, src/shell/body_nav.nim:305-306); the planning scheduler never reads it (:572-619), so a dead seat can keep spending work.

Measurements from the task (arm64 release, 16 seats, BR pool maps 0/21/42/63): cold far routes finish in 10-21 scheduler ticks; alternating goals for 32 ticks spent and discarded all 131,072 allowed units on every map with zero-movement counts of 260/512, 286/512, 483/512 and 428/512 seat-ticks; a no-path seat at index 15 waited 6-11 ticks for its first planning visit. Process peak RSS ~2.37 GB. Focused suites pass (test_shell_body_nav 20/20, test_shell_body_seat 22/22): the liveness cases are uncovered, not red.

Why the memory is that large (giant map: 85,814 nav cells, 344,487 lattice nodes; `newBodyPlanner` sizes every workspace to the full lattice, src/shell/body_planner.nim:252-270; `newBodyNavSystem` allocates one planner, one cache and one path buffer per seat, src/shell/body_nav.nim:197-233):

| Per-seat allocation (giant map) | Bytes |
|---|---|
| A* heap nodes (40 B x 344,487) | 13.8 MB |
| heap positions + generations (2 x 8 B x 344,487) | 5.5 MB |
| search hash tables (3 x 8 B x 1,048,576) | 25.2 MB |
| keys / closed / gScore / cameFrom | 8.6 MB |
| planner result path (16 B x 344,487) | 5.5 MB |
| follower path buffer (16 B x 344,489) | 5.5 MB |
| 4 route-field rasters (85,814 x 9 B each; src/shell/body_cache.nim:54-64, types.nim:441) | 3.1 MB |
| danger field + visited raster (2 x 4 B x 85,814) | 0.7 MB |
| Total per seat | ~68 MB; x32 seats ~2.2 GB |

## 2. What the design keeps from the existing code

- `BodyMap` (src/shell/body_map.nim) is already an immutable per-episode terrain layer: 1 px wall and clearance rasters (chessboard EDT), pixel components, the 8 px nav grid (`NavCell = 8`, :13; `walkable` = clearance at the cell centre > `PlayerHalf` 6), watershed rooms over clearance with chokes at room contacts deduplicated at 64 px (`GateSeparationPx`, :20; `buildTopology` :482-658), the cover atlas, validator tables (`validateGoal` :397-412, the sole constructor of `ValidatedGoal`), and home fields. `roomLabelAt` (:190-192) returns a ONE-based label; `BodyRoom`/`BodyChoke.roomA/roomB` are ZERO-based indices (:194-205, :633-654).
- The exact collision predicate: `canStand` (:164-165) plus the pixel-exact `segmentClear` (src/shell/body_planner.nim:298-329). The planner's edge legality is `canStand` + `segmentClear` for every lattice step (:610-617).
- The cost model: step length x (1 + profileDangerWeight x danger(midpoint)), x8 (`FollowBlockFactor`, :18) when the midpoint's nav cell is the blocked-penalty cell (:618-628); profile weights cpDefault 1.0 / cpCarrier 2.5 / cpHunter 0.25 (:88-92).
- The follower shape: path buffer + cursor, waypoint advance within one NavCell, corridor 20 px, stuck after 8 ticks, blocked penalty 96 ticks (src/shell/body_nav.nim:38-43, :687-717).
- The per-seat danger field and its 32-tick staggered rebuild from at most eight visible enemies (src/shell/body_nav.nim:30, :44, :440-485).
- The sim's once-per-episode zone paint-arrival field: `ZoneArrivalField` has TWO surfaces, `damage` (ungated, what `zoneDamageByPaint` reads) and `arrival` (render-gated, may say never under wall art) (src/ctf/zone_field.nim:1593-1616); `zonePaintedForDamageAt` reads `damage` against the schedule's ELAPSED clock (`sim.tickCount - sim.gameStartTick`) (:1762-1796); grid stride 4 px (`ZoneFieldCellPx`, :65); sentinel `ZoneNeverArrives = 0xFFFF` (:263); built lazily by `ensureZoneArrivalField` (:1644-1662).
- From PR #408: the conservative MIN projection of the 4 px field onto the 8 px nav grid, the finite hazard price (never a prune), the derated ETA speed MaxSpeed*3/(MotionScale*4) = 2.0625 px/tick (top speed is 704/256 = 2.75 px/tick, src/ctf/sim_types.nim:514-518), and the 48-tick safe-horizon bucket. From #409: the fog-safe integer nav hints (ticks until paint here, ticks to safety, geodesic safe distance in px, retreat octant). From #410: `navigate_to target_class = "zone_safe_ground"` with a REQUIRED literal fallback point, resolved by the engine.

## 4. Proposed design

Overview in one sentence: build one immutable room/portal route index per map install, attach one immutable zone hazard overlay per episode, answer every route request synchronously with a bounded search over the portal-side graph plus bounded endpoint refinement, execute the chosen legs by reading the index, and steer locally with a deterministic eight-octant rule whenever no advancing route exists.

### 4.1 BodyRouteIndex (map install, immutable, episode-shared)

Built from `BodyMap` inside the same activation barrier, before `newBodyNavSystem`. Deterministic by construction: all loops run in room index, choke index and row-major cell order; no tables keyed by pointer or hash iteration.

Data (sizes for pool:1 giant / colossal):
1. `legalMoves: seq[uint8]` per nav cell, bit i = the move to canonical `Neighbors[i]` is legal: both cells walkable, no corner cutting, and pixel `segmentClear` between the centres. This is the ONE legality oracle for the index build, the follower's smoothing, the local search and the steering. `segmentClear` and `Neighbors` move to body_map so there is exactly one implementation (today they are duplicated across body_map.nim:24-27 and body_planner.nim:20-22, :298). 86 KB / 343 KB.
2. Room compaction: `roomOf: seq[uint16]` per nav cell (zero-based room index), `roomCellStart`, `roomCells` (cell indices per room in row-major order), `localIndex: seq[int32]` per nav cell. Build ASSERTS every walkable cell has a room (measured: always true on 8 maps). ~0.6 MB / 2.4 MB.
3. Portals = BodyMap chokes, two-sided: for each choke an anchor cell on the roomA side and one on the roomB side (nearest walkable cell of that room to the choke pixel within a bounded ring, fixed ring order) and the legal crossing between them (a direct legal edge, or a bounded build-time search whose cells are stored as a crossing segment). Activation asserts every portal reaches both rooms. Measured anchor mismatches on the naive one-sided rule: 0-12 per map.
4. Portal fields: for each (room r, portal p of r) one `uint8` NEXT-HOP per cell of r (the legal neighbour index toward p's anchor on r's side, from one room-restricted Dijkstra; ties by `Neighbors` order). Distances are not stored: a query that needs the distance from a cell to p walks the chain, which exact scoring does anyway (max chain measured 213 cells giant / 436 colossal). The Dijkstra uses a transient `uint32` distance array over one room, reused. 1.7 MB / 9.5 MB.
5. Intra-room segments: for every portal pair (p < q) of a room, the cell path p -> q read off p's Dijkstra parents, stored flat (`segmentCells: seq[int32]`, start/len, static length as `uint32` in 1/16 px, bounding box). Pairs unreachable inside the room get no segment (measured 1-5 % of pairs); the abstract graph routes around them through other rooms. 0.9 MB / 3.1 MB.
6. Portal-side graph: nodes are (portal, incident room) SIDES (<= 2,474 on colossal); edges are the intra-room segments between sides of the same room (<= 27,460 directed) plus one crossing edge per portal between its two sides (<= 2,474 directed). Because the crossing is an edge, a room change always pays the crossing's length, danger, blocked and hazard cost, and every chosen edge names exactly one segment.

Retained total: ~3.5 MB giant (limit 16 MiB), ~16.3 MiB colossal (limit 32 MiB). Transient build workspace: one heap and one distance array over ONE room (max 70,041 cells), reused. Build time measured by the probe (which stored full distance fields and reused none of the parents, so it is an upper bound on this shape): 189-283 ms on giant maps against a 479-499 ms BodyMap baseline (total 1.4-1.6x, cap 2x), 2,245 ms on colossal against 2,263 ms (total 2.0x, cap 3x). The canonical linux/amd64 numbers come from subtask 02's gate run.

Coverage proof (subtask 02, offline, exhaustive, every supported map): every standable pixel has a legal <= 32 px pixel connector to an anchored nav cell of the same pixel component, and two anchored cells are graph-connected exactly when their pixel components are equal. The probes already show pool:0 splits one pixel component into two legal 8 px components (a 34-pixel pocket), so this is an invariant to prove, not a sample to hope for. If the proof fails on any map, sparse 4 px micro-corridor nodes are added where it fails before qualification. The route corpus is the cost test only, never the topology proof.

### 4.2 BodyHazardOverlay (episode, immutable) and BodySafeCache (episode, mutable, bounded)

Server seam: in `resetFirstLightForSim` (src/ctf/server.nim:3857-3870), after `newBodyMap`, when `season2Shell and zoneDamageByPaint and zonePhases.len > 0`: call `ensureZoneArrivalField(sim)`, snapshot `damage` (never `arrival`), the grid dims and the field fingerprint, build the overlay, then construct the nav system. Otherwise the overlay is a typed DARK state: no hazard term, hints absent, class targets unresolvable so the literal fallback stands. Nothing is built lazily on the play path.

The overlay is schedule-relative and origin-free: `gameStartTick` is -1 until `startGame` enters Playing (src/ctf/sim.nim:1694-1696, :6679, :6750), which happens after FirstLight is constructed, so no origin is snapshotted. The server passes the live elapsed zone tick (the same `sim.tickCount - sim.gameStartTick` every zone consumer reads) into the FirstLight step, and hazard ETA, safe buckets and hints all use it.

Overlay data: `arrival: seq[uint16]` per nav cell = MIN over the 4 px source cells the nav cell covers (PR #408's projection, conservative); per segment `arrivalMin/arrivalMax` used only to skip segments that are provably zero-risk or provably saturated; per room `maxDamageArrival` (never-arrives treated as infinity). 172 KB / 686 KB.

Safe cache, keyed by (overlay fingerprint, game generation, horizon bucket = 48 ticks), recomputed once per bucket roll and re-keyed if elapsed time ever moves backwards: the set of DRY portal sides (arrival > bucket end + horizon) seeds one multi-source Dijkstra over the side graph (static lengths) giving `safeDistPx[side]` and `safeNext[side]`; the per-room flag "contains a dry cell" comes from `maxDamageArrival` in O(rooms) (302 on colossal). Microseconds of work; no full-grid flow field and no full-grid scan is ever run on a bucket roll (PR #408 re-minted a full field every 48 ticks; rejected).

Per-seat safety answers (PR #409 contract, integers, fog-safe because the paint front is public): own cell dry -> ticks_to_safety 0; else if the own room has dry cells -> bounded legal BFS from self (fixed cap, 512 cells) for the nearest dry cell; else the best of (walked chain distance to side s + safeDistPx[s]) over the room's portal sides. Direction = the first step of the winner as an octant. Every resolved source must satisfy the dry predicate (asserted) or the answer is "unreachable" and the play's literal point stands. `zone_safe_ground` identity = (class, resolved source cell); the bucket is cache provenance, not intent identity, so an unchanged target never causes route churn. Resolution runs before the arrived test in `seatTick`, so the effective goal is the class target, not the fallback.

### 4.3 Live route query (synchronous, bounded, runs only when a request changes)

Inputs: seat position, `ValidatedGoal`, cost profile, the seat's danger field, blocked-penalty cell, overlay, elapsed zone tick.
1. Endpoint attach, both ends: candidate anchor cells within a ring of <= 4 nav cells (32 px, today's `EndpointSnapPx`, src/shell/body_planner.nim:16) in fixed ring order, accepted only if the exact pixel segment anchor <-> endpoint passes `segmentClear`. No candidate -> typed failure (the follower keeps an advancing old route if any, else steering). The route always ends at `goal.goalPoint` itself, as the current planner's path does (src/shell/body_planner.nim:666-676). `BodyMap.nearestWalkable` (unbounded ring, src/shell/body_map.nim:418-427) is not used on the play path.
2. Same-room candidates when start and goal share a room: (a) the straight line if every cell step along it is legal; (b) via the best portal side of the room by walking both next-hop chains (O(degree x chain) reads, stays inside the room); (c) a bounded weighted room-local A* over `legalMoves` in a shared generation-stamped workspace with a FIXED expansion cap that is a latency-derived constant (4,096 is the starting hypothesis; it is never derived from room size, because rooms reach 70,041 cells). All candidates are scored with the full cost model; the cheapest wins; a cap hit simply drops candidate (c).
3. Side-graph A*: start and goal are virtual nodes attached to their rooms' portal sides with exactly scored chains (danger, blocked cell, hazard advanced cell by cell); edge cost = static length + danger-weighted cost + blocked factor + hazard price; heuristic = the exact integer octile distance 181 x min(dx,dy) + 128 x (max(dx,dy) - min(dx,dy)) over CELL-INDEX deltas between anchors (admissible for the encoded metric; the golden oracle states this formula and every rounding rule so the integer implementation and the reference cannot disagree by convention); ties by (cost, side index); a constant expansion cap (4,096 pops, above the side count of any supported map) that only guards bugs. Workspace arrays are sized by side count and SHARED across seats (queries are sequential), generation-stamped so nothing is cleared per query.
4. Danger-weighted segment costs are memoised in ONE shared query-local memo keyed by edge ID: a 4 B value plus a 2 B generation stamp per directed edge (27,460 x 6 B = 165 KB on colossal, counted in the retained shared total); nothing is memoised per seat and nothing is cleared per query. The blocked factor is applied to segments whose bounding box contains the blocked cell and whose cell list contains it.
5. Hazard price per edge: start from the entry ETA, advance the ETA along the segment's cells by their 1/16 px lengths at 2.0625 px per tick (integer ratio), and apply the finite ramp at each cell in traversal order; the per-segment extrema only skip provably zero or provably saturated segments. Finite, never a prune.
6. Assemble the whole route descriptor in shared query scratch: ordered edge IDs with direction, the copied start leg or local leg, the copied goal leg, the exact endpoint connectors. Validate every leg. Only then copy into the seat's fixed buffers (edge descriptors: 4,096 entries, a safe bound because a non-negative shortest path is simple, asserted at activation; start/local and goal leg buffers sized from the search cap and the measured max chain, 512 cells each; measured max chain 213 giant / 436 colossal) and flip the route revision. A failed query never touches the active route.

Cost estimate on giant, to be replaced by subtask 09's numbers: attach <= 2 x 46 sides x <= 213 cells = ~20k cell reads; A* <= 738 sides / 8,748 directed edges with O(1) memoised edge cost; cold memo fill bounded by the segments actually relaxed (worst case every segment: 224,822 cell reads, ~0.2-0.4 ms; this is the one estimate that could threaten the 5 ms max if all 16 seats query cold in the same tick, so the benchmark includes exactly that burst and the fallback is sampling every second cell).

### 4.4 Following and immediate movement (every navigate tick)

- The follower executes legs from the descriptor instead of a map-sized path: the start/local leg and the goal leg from the seat's copied buffers, middle legs read from the index by (edge id, direction, offset), crossings from the stored crossing cells, then the pixel connector to the exact goal. Waypoint advance, corridor, stuck and blocked-penalty rules keep their current values.
- Follow-time smoothing: look ahead up to K = 6 cells along the current leg and target the farthest point whose exact pixel segment from the cog's actual position is `segmentClear`. This removes portal-point kinks and octile zig-zags and is what keeps short gate crossings under the 3 % gate; the corpus measures executed masks, so the smoothing is inside the measurement.
- An advancing route is one whose next waypoint is farther than the arrive radius from the cog. An arrived endpoint is NOT an advancing route.
- Local steering whenever there is no advancing route (a failed query, an exhausted route while the goal changed): evaluate the eight octants in `Neighbors` order; candidate = self + 8 px along the octant; reject if not `canStand`, not pixel `segmentClear`, or the blocked-penalty cell; score = distance-to-target reduction (target = next waypoint if any, else the goal) minus profile-weighted danger minus hazard price, integers; pick the maximum, ties by octant order; no progressing candidate -> stand and record `bnsNoProgress`. O(8), allocation-free.
- Diagnostic states become: idle, following, steering, no-progress, arrived. `bnsStalePath` is removed: it can no longer claim motion while the cog is stationary.

### 4.5 Request lifecycle

- `setStandingIntent` no longer touches navigation at all (the cancel at src/shell/body.nim:582-583 and the goal pin both go; pins die with the route-field slots). The nav coordinator owns every request decision.
- Route anchor = goal cell of the last ACCEPTED request (installed or failed). A query runs iff: no route this life; or the goal cell differs from the anchor by more than 2 cells (`ReplanGoalCells`) on either axis; or the profile changed; or stuck for 8 ticks; or a moving goal and 12 ticks since the last query; or the current route is exhausted. Sub-threshold moves do not move the anchor, so cumulative one-cell drift eventually triggers. Epoch and provenance changes are invisible to navigation.
- Queries are synchronous, so there is no pending state and nothing to cancel; the replacement is ready in the same call. On a failed query the old route is kept only while it advances; otherwise steering.
- Death (`resetAfterDeath`, src/shell/episode.nim:987-997): clear route descriptors, leg buffers, cursor, anchor, revision, lastXy, stuckTicks, blocked penalty, last-query tick, follow counters, desired profile/moving flags and semantic target identity, THEN `setSeatActive(false)`. Inactive seats are skipped by the danger rebuild (already true, src/shell/body_nav.nim:481-483) and asserted never to be queried. Shared index, overlay and safe cache persist.

### 4.6 Arithmetic and determinism

- Search costs are integers in 1/16 px: orthogonal step 128, diagonal 181, with the exact integer octile heuristic above (a Euclidean heuristic in these units is NOT admissible: 181/128 = 1.4140625 < sqrt 2, and 53 diagonal steps already expose it). Danger is sampled from the existing float32 field and quantised to 1/256 at the point of use (at most 0.49 % relative error on a carrier-profile path, reported against the unquantised oracle); profile weights are integer ratios over 256 (256, 640, 64); blocked factor 8 exact; hazard ramp in integer ticks; every rational product rounds to nearest; totals in checked int64. The cost-gate ORACLE stays the task's 4 px float formula and scores the returned route with it; the search's quantisation is what the gate must see, so the oracle never adopts it.
- No clocks, threads, async work, pointer identity or hash-iteration order anywhere in route choice. Replays re-drive input masks, and no body_* module is in the wasm build (verified in PR #408), so archived replays stay valid; movement masks change, so a collision-free `GameVersion` (currently "52", src/ctf/sim_types.nim:58), all NINE fixtures (AGENTS.md:377-401) and the committed replay viewer are re-recorded after the gates pass.

### 4.7 Deleted

`BodyPlanner` and its lattice workspace, `BodyFieldMinter`, route-field slots in `BodySeatCache` (`MaxRouteFieldsPerSeat`, pins, `peekRouteDistance`), plan/mint jobs, `ColdPlanBudgetPerTick`, `runPlanningTick`, `prewarmColdPlans`, plan budget events and traces, scheduler cursors, `bnsStalePath`. The duck cache stays (cover-hold owns it). Per-seat route-query state drops from ~68 MB to about 12 KB (edge descriptors 8 KB, two 512-cell leg buffers 4 KB); the per-seat danger and visited rasters (0.7 MB giant, 2.75 MB colossal) are unchanged and outside this task (a uint8 danger raster with a shared visited raster is a listed follow-up).


## 5. Decisions and rejected alternatives

- HPA*-style room/portal index over BodyMap's rooms and chokes. Rejected: JPS (its benefit assumes uniform static costs; here costs are profile-weighted danger, blocked cells and zone time); Recast/Detour (right behaviour model, but a C++ 3D navmesh and FFI dependency for a deterministic integer-bitmap Nim sim); D* Lite (targets changing edge costs; here topology is static and goals churn); continuum crowds (amortises shared destinations; seats have distinct goals and danger fields). No maintained Nim package covers deterministic hierarchical game navigation. Also rejected: keeping the resumable scheduler with priority for no-route seats (still map-sized per-seat state, still hundreds of ticks for far routes, and steering alone would leave cogs walking greedily into dead ends for seconds).
- 8 px cells with centre anchors and exact pixel endpoint connectors as the baseline. Rejected as baseline: a 4 px index (4x the field memory, ~76 MB on colossal, over the limit); per-cell sub-lattice anchors plus sparse 4 px micro-corridor nodes (the Codex reviewer's preference; kept as the documented CONTINGENCY if the corpus gate reports a missing route, because the probes show the spawn component keeps 98.7-99.3 % of standable pixels and the connector covers the rest on sampled maps).
- One static segment per portal pair, scored dynamically, plus bounded weighted refinement in the endpoint rooms. This is the task's explicit trade ("dynamic global danger may select among precomputed structural route segments; the engine does not need the exact cell-by-cell dynamic optimum"). Rejected: storing k alternative segments per pair (more memory, no evidence it is needed; the gate decides).
- One shared, query-local segment-cost memo keyed by edge ID. Rejected: eager per-seat refresh at every danger rebuild (touches every segment every 32 ticks whether or not a query consumes it: 13,730 segments per seat per generation on colossal); a per-seat lazy memo (13,730 x 4 B = 55 KB per seat on colossal, against the intent that per-seat query state stays tiny).
- Route = ordered edge IDs with direction over a portal-SIDE graph, legs executed from the index, endpoint legs copied into small fixed buffers, the whole descriptor validated in shared scratch before an atomic copy. Rejected: a per-seat flat cell buffer with prefix truncation (a second query/install lifecycle for a case that "cannot occur", and a silently accepted prefix is not a route); an ordered PORTAL list over collapsed portal nodes (lets the search change rooms without paying the crossing and cannot say which of two parallel segments won); live descent on the static portal field for the start leg (discards a weighted local result and reads a shared workspace the next query overwrites).
- Follow-time smoothing with the exact pixel predicate from the cog's real position. Rejected: query-time polyline smoothing (the cog is rarely on the polyline; a Bresenham walk over cells proves a staircase, not the chord).
- Semantic target identity = (class, source cell), not the bucket. Rejected: bucket in the identity (forces a replan every 48 ticks with an unchanged target).
- Hazard overlay is immutable; the per-bucket safe results live in a separate bounded cache. Rejected: one object with both (contradicts the ownership and lifecycle claims).
- Integer fixed-point costs (128/181) with the exact integer octile heuristic; uint8 next-hop portal fields. Rejected: float costs (tie outcomes drift across builds); a Euclidean heuristic in the same units (inadmissible, 181/128 < sqrt 2); uint16 distance fields (twice the memory and 1/16 px units overflow on a 436-cell chain); an oracle that shares the search's quantisation (would hide exactly the error the 3 % gate exists to catch).
- Zone data: consume `damage`, gate on `zoneDamageByPaint`, the live elapsed zone tick passed into the step. Rejected: `arrival` (false safe lanes under wall art); the absolute sim tick (the schedule runs on elapsed ticks); snapshotting `gameStartTick` at FirstLight construction (it is -1 until `startGame`, and changes between games).
- Room "contains dry cells" from a per-room `maxDamageArrival` computed once at overlay build. Rejected: a linear pass over all nav cells on every bucket roll (343,256 reads every 48 ticks on colossal for a value that never changes).

## 6. Gates (from the task; the design must pass, not redefine, them)

- Legality and reachability: every route collision-legal, ends at the same validated goal and component as the current planner; a missing route is a failure, never a sample.
- Cost inflation against the checked-in literal corpus (64 pool maps; 16-seat published and 32-seat supported rosters; cpDefault/cpCarrier/cpHunter; four dynamic snapshots: none, literal danger, literal blocked cell, both; near/far): C(R) = sum over consecutive steps after deterministic 4 px resampling of Euclidean step length x (1 + profileDangerWeight x danger(midpoint)), x8 when the midpoint's NavCell is the blocked cell; inflation = 100 x (C(candidate) - C(current)) / C(current); p95 <= 3.0 % and max <= 10.0 %, overall and within every stratum, each stratum reported separately; an empty stratum is a failure. After cover-hold lands, the corpus gains a cold transition to a cover goal.
- Body time on linux/amd64 Docker release (Nim 2.2.4, pinned nimby.lock, -d:release -d:useMalloc --threads:on --opt:speed, one production-equivalent CPU, five warmups, 30 repetitions): complete FirstLight body slice p95 <= 4.0 ms and max <= 5.0 ms for 16 and 32 seats, timed inclusively (every seat body tick, danger rebuild, query, steering, bookkeeping; not guest runtime or view encoding), on the hard cases: simultaneous first goals for all seats, all-seat moving-goal replans, bucket and danger-generation rollover ticks, stuck replans, worst-degree rooms, cold memo.
- Activation: map + index within 2x the current BodyMap baseline on every published pool map and 3x on colossal, same image, same run; retained shared nav data <= 16 MiB (pool) / <= 32 MiB (colossal); transient build peak reported separately.
- No active-play tick schedules or advances a full-grid search: asserted in tests and diagnostics. Per-seat query state contains no array sized by map width, height or fine-node count (asserted at activation).
- GameVersion, nine fixtures, viewer rebuild after the gates.

## 7. Risks and mitigations

- Cold memo burst (all seats query in the same tick with empty memos): benchmark exactly that; fallback is sampling every second segment cell (halves the reads) or a per-tick memo-fill cap that degrades remaining edges to static cost deterministically.
- Rooms are huge (70k cells): the same-room path relies on the straight line, the via-portal candidate and a local A* with a fixed latency-derived cap (never a cap derived from room size); on a cap hit the portal candidate's full inflation counts in its stratum, and failing the 10 % max means adding structural alternatives to the index rather than raising the playing-tick cap.
- Static segment cannot dodge danger inside a room: accepted trade per the task; endpoint refinement and the gate bound it.
- Portal pairs unreachable inside their room (1-5 %): the abstract graph routes through neighbouring rooms; if the gate shows inflation from this, extend the build-time Dijkstra to a bounded margin outside the room.
- Two-sided portal anchors that cannot be joined by a bounded crossing search: activation failure with a message naming the choke; measured mismatch counts are 0-12 per map.
- Hazard arrival estimate is conservative-late: safe only because the hazard is a price; the doc and the code carry the warning from PR #408.
- Zone clock origin drift (e.g. a config reload mid-episode): the overlay stores the fingerprint; a mismatch at the safe-cache key is an assertion, not a silent stale answer.
- Determinism drift between arm64 development and linux/amd64 canonical builds: integer arithmetic everywhere in route choice; the corpus hashes are compared across both.
- Search-side danger quantisation (1/256) versus the float oracle: bounded at 0.49 % relative on a carrier-profile path; reported, never hidden by quantising the oracle.
- Single-label search versus time-dependent hazard: the side-graph A* carries one (cost, physical length) label per node, but a slightly dearer, shorter prefix can reach a later segment before the paint does. Qualification includes that adversarial case; if the single-label search misses the intended safe route, the search keeps an earliest-arrival alternative label per node, never a larger playing-tick cap.
